# تصميم الحزمة المهنية

اتبعت هذه الحزمة نمط Athar Docs الذي أشار إليه المستخدم: مصدر مهارة معياري، سير عمل محدد حسب الطلب، قواعد وأدلة، ملفات تحقق، ونسخة توزيع تُولد وتُفحص من المصدر. لم تُنسخ قواعد التوثيق الخاصة بـ Athar لأنها لا تخص Zoho.

## ملكية الملفات

- `.agents/skills/zoho-sprints/` هو المصدر الوحيد الذي يُحرَّر. `SKILL.md` يوجه إلى workflow المناسب ويحتوي القرارات المشتركة فقط.
- `references/policy-contract.md` يملك قواعد الدور والخصوصية والإنشاء والاستعادة؛ `contract.json` يملك قيم الحالات والمسارات الأساسية.
- `workflows/` يحدد خطوات العمليات الست؛ `checks/` يحدد أدلة القراءة والكتابة واستمرار التدقيق.
- `assets/` قوالب تُنسخ إلى المشروع المنفذ عند الحاجة، لا تعليمات إضافية ولا بيانات اتصال.
- `skills/zoho-sprints/` نسخة توزيع مولدة من المصدر بأمر `npm run sync`. يتحقق `npm run check` من تطابق الملفات والروابط والعقد والـ manifest.
- `tools/install.mjs` يثبت المهارة كاملة في مسار المحرر المختار. التحديث القسري يجهز النسخة أولًا ويحفظ السابقة خارج مسار اكتشاف المهارات.

## حدود التشغيل

ملف MCP وعنوانه الخاص خارج الحزمة. في مشروع الإعداد هذا يوجد داخل `docu/mcp_sprint_config.json` ويقرأه مشغّل محلي في الجذر. عند نقل الحزمة إلى مشروع آخر، يضبط كل محرر خادم MCP وOAuth بنفسه. ملف الدور `.zoho-sprints/profile.yaml` وحالة التدقيق المحلية يبقيان في المشروع المنفذ، لا في الحزمة.

لا يوجد افتراض دائم لأسماء الأدوات أو مخططاتها. مشاهدة 83 أداة بتاريخ 27 أكتوبر 2026 تصلح كدليل اختباري، ثم يعاد اكتشاف الأدوات عند كل استخدام. وجود أداة إكمال Sprint لا يثبت صلاحية الحساب أو استيفاء شروط إغلاق العمل غير المكتمل.
