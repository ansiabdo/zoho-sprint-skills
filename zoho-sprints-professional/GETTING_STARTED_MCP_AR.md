# دليل البدء وربط Zoho Sprints MCP واستخدام المهارة

آخر مراجعة: 2026-10-28. هذا الدليل يرافق حزمة zoho-sprints-professional. أمثلة الاتصال تستخدم عنوانًا بديلًا؛ استبدله بعنوان خادمك الفعلي داخل إعداداتك الخاصة فقط.

## 1. ما الذي تحتاجه؟

- مشروع عمل مفتوح في المحرر؛ لتحليل التغييرات يجب أن يكون مستودع Git فعليًا.
- حساب Zoho مخول للوصول إلى مساحة العمل والمشروع.
- عنوان خادم Zoho Sprints MCP وطريقة مصادقته من مسؤول الاتصال.
- Node.js 22 أو أحدث لتشغيل مثبت هذه الحزمة؛ الاتصال البعيد المباشر لا يتطلب Node بحد ذاته.
- مجلد الحزمة كاملاً. لا تنقل SKILL.md وحده لأن المهارة تقرأ workflows وchecks ومراجع وقوالب أخرى.

هناك إعدادان: ربط MCP يتيح الأدوات، وتثبيت المهارة يحدد طريقة استخدامها. بعدهما يحدد profile مشروع Zoho وهوية المستخدم ودوره. اختيار مجلد الكود في المحرر لا يحدد مشروع Zoho تلقائيًا.

## 2. ثبّت المهارة في مشروع العمل

مثال: مجلد الكود هو C:\work\my-system، والحزمة عندك في F:\zoho sprint skills\zoho-sprints-professional. من PowerShell:

```powershell
Set-Location 'F:\zoho sprint skills\zoho-sprints-professional'
node tools/install.mjs --editor codex --target 'C:\work\my-system'
```

غيّر codex إلى قيمة محررك:

| المحرر | قيمة --editor | مكان المهارة داخل مشروع العمل |
|---|---|---|
| Codex | codex | .agents/skills/zoho-sprints/ |
| Antigravity | antigravity | .agents/skills/zoho-sprints/ |
| Cursor | cursor | .cursor/skills/zoho-sprints/ |
| Kiro | kiro | .kiro/skills/zoho-sprints/ |
| OpenCode | opencode | .opencode/skills/zoho-sprints/ |
| Claude Code | claude | .claude/skills/zoho-sprints/ |
| بيئة تدعم .agents/skills | generic | .agents/skills/zoho-sprints/ |

أداة التثبيت ترفض استبدال نسخة موجودة. للتحديث بعد مراجعة النسخة استخدم --force؛ تحفظ القديمة في .zoho-sprints-skill-backups داخل مشروع العمل. افتح جلسة جديدة أو حدّث قائمة المهارات في المحرر عند الحاجة. مسارات المهارات موثقة أيضًا في [دليل المحررات](editor-guides/README_AR.md).

## 3. اربط MCP في المحرر

استبدل https://YOUR-ZOHO-MCP-ENDPOINT بعنوان الاتصال الكامل الذي زودك به مسؤول الخادم. لا تخمن المنطقة أو تضف /mcp أو /sse إلى العنوان من عندك. الأمثلة لاتصال HTTP مباشر عندما يدعمه خادمك؛ النقل والمصادقة يجب أن يتوافقا مع خادم Zoho الفعلي. ادمج الإعداد مع الملف الموجود؛ لا تستبدل خوادمك الأخرى.

### Codex

أضف في .codex/config.toml داخل مشروع موثوق، أو في إعداد المستخدم ~/.codex/config.toml:

```toml
[mcp_servers.ZohoMCP]
url = "https://YOUR-ZOHO-MCP-ENDPOINT"
```

أو أضف اتصال المستخدم عبر CLI:

```powershell
codex mcp add ZohoMCP --url 'https://YOUR-ZOHO-MCP-ENDPOINT'
codex mcp login ZohoMCP
codex mcp list
```

نفذ login إذا كان الخادم يستخدم OAuth. وجود اسم الخادم في القائمة يحتاج بعده تجربة قراءة فعلية. لا تضف اتصالًا ثانيًا بالاسم نفسه إذا كان الاتصال مضبوطًا بالفعل. [توثيق Codex MCP](https://learn.chatgpt.com/docs/extend/mcp).

### Cursor

في .cursor/mcp.json داخل مشروع العمل:

```json
{
  "mcpServers": {
    "ZohoMCP": {
      "url": "https://YOUR-ZOHO-MCP-ENDPOINT"
    }
  }
}
```

افتح إعدادات MCP في Cursor، تحقق من تفعيل الخادم، وأكمل المصادقة عند طلبها. [توثيق Cursor](https://prod.cursor.com/help/customization/mcp).

### Kiro

في .kiro/settings/mcp.json داخل مشروع العمل:

```json
{
  "mcpServers": {
    "ZohoMCP": {
      "url": "https://YOUR-ZOHO-MCP-ENDPOINT"
    }
  }
}
```

تحقق من حالة الخادم وأكمل OAuth من واجهة Kiro عندما يطلب ذلك. إعداد مساحة العمل يمكنه تجاوز إعداد المستخدم بالاسم نفسه. [توثيق إعداد Kiro](https://kiro.dev/docs/mcp/configuration/).

### OpenCode

ادمج في opencode.json بمجلد مشروع العمل:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "ZohoMCP": {
      "type": "remote",
      "url": "https://YOUR-ZOHO-MCP-ENDPOINT",
      "enabled": true
    }
  }
}
```

إذا احتاج الخادم OAuth:

```powershell
opencode mcp auth ZohoMCP
```

[توثيق OpenCode MCP](https://opencode.ai/docs/mcp-servers/). راجع صيغة إصدارك إذا كان مختلفًا عن الوثائق الحالية.

### Antigravity

من لوحة الوكيل افتح MCP Servers ثم Manage MCP Servers وView raw config. يمكن وضع إعداد المشروع في .agents/mcp_config.json:

```json
{
  "mcpServers": {
    "ZohoMCP": {
      "serverUrl": "https://YOUR-ZOHO-MCP-ENDPOINT"
    }
  }
}
```

هذا المثال لنقل Streamable HTTP؛ إذا كان اتصالك يحتاج جسر stdio فاستخدم طريقة الجسر أدناه بدل افتراض توافق النقل. [توثيق Antigravity MCP](https://antigravity.google/docs/mcp).

### جسر stdio الموجود في مشروع الإعداد الحالي

الاتصال الذي جُرّب في هذا المشروع يستخدم mcp-remote عبر المشغل المحلي:

- F:/zoho sprint skills/mcp/zoho-mcp-launcher.js
- ويقرأ F:/zoho sprint skills/docu/mcp_sprint_config.json.

يمكن للمحرر الذي يدعم stdio تشغيله محليًا. مثال Cursor أو Kiro أو Antigravity ضمن mcpServers:

```json
{
  "mcpServers": {
    "ZohoMCP": {
      "command": "C:\\Program Files\\nodejs\\node.exe",
      "args": ["F:\\zoho sprint skills\\mcp\\zoho-mcp-launcher.js"]
    }
  }
}
```

وفي Codex، بدلاً من url:

```toml
[mcp_servers.ZohoMCP]
command = "C:\\Program Files\\nodejs\\node.exe"
args = ["F:\\zoho sprint skills\\mcp\\zoho-mcp-launcher.js"]
startup_timeout_sec = 60
```

وفي OpenCode، قيمة الخادم داخل mcp تكون:

```json
{
  "type": "local",
  "command": ["C:\\Program Files\\nodejs\\node.exe", "F:\\zoho sprint skills\\mcp\\zoho-mcp-launcher.js"],
  "enabled": true
}
```

اختر الاتصال المباشر أو الجسر، كيلا تتكرر الأدوات. هذه المسارات خاصة بهذا الجهاز؛ مجلد الحزمة لا يتضمن المشغل وإعداد الاتصال الخاص. عند الانتقال لجهاز آخر جهز اتصالًا مستقلًا، ولا تتوقع أن يعمل مسار F: هناك. المصادقة الخاصة بالجسر قد تختلف عن مصادقة المحرر المباشرة.

### ChatGPT والمحررات الأخرى

ChatGPT الويب لا يقرأ .codex/config.toml من جهازك. استخدم إعداد Apps/MCP المتاح لحسابك وسياسة مؤسستك لربط الخادم البعيد وإكمال المصادقة. إذا لم تتوفر إضافة اتصال مخصص فستحتاج تمكينها من مسؤول الحساب. [مرجع اختلاف اتصال ChatGPT وCodex](https://learn.chatgpt.com/docs/extend/mcp).

أتح مجلد المهارة عبر استيراد Skills إذا كان متاحًا، أو أتح ملفاتها كمراجع للمشروع وأضف تعليمات صريحة بقراءة SKILL.md والعقد والـ workflow المناسب. لا يُفترض أن دعم MCP يعني دعم Skills. تحليل Git المحلي يتطلب وصولًا فعليًا للمستودع؛ اتصال Zoho وحده لا يتيح ملفات جهازك.

في أي محرر آخر اتبع إعداد MCP الرسمي لديه، ثم آلية المهارات أو تعليمات المشروع التي يدعمها. لا تنسخ صيغة JSON الخاصة بمحرر إلى آخر إذا كانت مخططاتهما مختلفة.

## 4. اختبر الاتصال أولاً

أرسل للوكيل:

> استخدم مهارة zoho-sprints. افحص اتصال ZohoMCP للقراءة فقط، واكتشف الأدوات الحالية ومخطط مدخلاتها. تحقق من قراءة بيانات مساحة العمل، ثم أخبرني بالنتيجة وحدود الاتصال دون إنشاء أو تعديل عناصر.

النتيجة المقبولة: استجابة قراءة فعلية ناجحة. ظهور أدوات الإنشاء وحده لا يثبت صلاحيتك ولا نجاح الكتابة. لا تستخدم ملفات المحادثات القديمة باعتبارها قائمة الأدوات الحالية.

## 5. حدد مشروع Zoho ودور المستخدم

داخل مجلد الكود أنشئ .zoho-sprints/profile.yaml من assets/profile.example.yaml الموجودة داخل مسار المهارة المثبتة. مثال Codex:

```powershell
Set-Location 'C:\work\my-system'
New-Item -ItemType Directory -Path '.zoho-sprints' -Force
Copy-Item -LiteralPath '.agents/skills/zoho-sprints/assets/profile.example.yaml' -Destination '.zoho-sprints/profile.yaml'
```

نفذ النسخ عند الإعداد الأول فقط كي لا تستبدل profile موجودًا. في Cursor/Kiro/OpenCode/Claude غيّر مسار المصدر بحسب جدول التثبيت.

محتوى الملف بعد استبدال القيم بمعرفات متحقق منها:

```yaml
role: developer
workspace_id: "VERIFIED_WORKSPACE_ID"
current_user_id: "VERIFIED_ZOHO_USER_ID"
timezone: "Asia/Aden"
default_project_id: "VERIFIED_PROJECT_ID"
language: ar
```

استخدم admin للأدمن أو developer للمطور. timezone مثال؛ تحقق من المنطقة المعتمدة قبل استخدامه. لا تكتب الاسم المعروض بدل ID، ولا تستنتج user ID من اسم Git. الملف يصف الدور المطلوب؛ صلاحيات الحساب الفعلية في Zoho تظل حاكمة.

لتحديد المشروع أرسل:

> دوري مطور. اربط مجلد هذا المستودع بمشروع Zoho المسمى «اسم المشروع» في مساحة العمل «اسم المساحة». تحقق من الهوية والدور من بيانات الاتصال المتاحة، وطابق الاسم بمعرف دقيق، واحفظ القيم المتحقق منها في profile المحلي. إذا تكررت الأسماء اعرض خيارات الاختيار المسموح بها. لا تعرض قصص مستخدمين آخرين ولا تنفذ أي كتابة في Zoho.

للأدمن استبدل «مطور» بـ «أدمن». عند تعذر إثبات هوية/دور المستخدم يبقى الاختبار عند بيانات الاتصال، ويُطلب استكمال الإعداد. عند تغيير مشروع Zoho راجع السجلات السابقة قبل تعديل الربط؛ لا تعِد استخدام checkpoint لمستودع أو مشروع مختلف.

أضف إلى .gitignore إن لم تكن موجودة:

```gitignore
.zoho-sprints/
.zoho-sprints-skill-backups/
.zoho-sprints-skill-staging/
```

احفظ إعدادات MCP التي تحتوي عناوين خاصة أو أسرار محليًا، ولا ترفعها ضمن مستودع مشترك. لا تضع رموز OAuth في profile أو ملفات المهارة.

## 6. التعامل بعد تحديد المشروع

### المطور: عرض عملي

> استخدم zoho-sprints والـ profile المحلي. اعرض فقط القصص والعناصر المسندة إلى معرفي في المشروع المحدد. افحص السبرنتات النشطة مع تواريخها، واذكر نطاق القراءة وأي صفحات تعذر الوصول إليها.

### المطور: إضافة Task أو Bug

> أضف Task بعنوان «تحسين التحقق من المدخلات» تحت القصة [ID]. تحقق أولاً أنها User Story مسندة لي، وافحص المهام الموجودة منعًا للتكرار. جهز وصفًا ونطاقًا ومعايير قبول، ثم أضفها وتحقق بقراءة النتيجة وسجل معرفها محليًا.

يجب أن تكون القصة مسندة إلى معرف المطور. إذا لم تكن كذلك يُعالج الإسناد أولاً وفق صلاحيات الحساب.

### المطور: Story جديدة أو الانضمام لقصة موجودة

> أريد قصة للعمل التالي: [الهدف]. افحص التشابه مع القصص الحالية قبل الإنشاء. إذا وجدت قصة تغطيه نبهني وفق نطاق العرض المسموح واعرض إمكانية انضمامي إليها. وإلا أنشئ القصة في Sprint نشطة تشمل اللحظة الحالية بين بدايتها ونهايتها بالمنطقة الزمنية المتحقق منها. إذا تأهلت أكثر من Sprint اطلب مني الاختيار.

لا يكفي أن تكون Sprint مفتوحة؛ يلزم تحقق الحالة والنافذة الزمنية. قصة مستخدم آخر لا تُعرض تفاصيلها للمطور قبل التحقق من إسنادها له. طلب الانضمام يحافظ على المسند إليهم الحاليين ويتطلب صلاحية فعلية.

### الأدمن

> استخدم دور الأدمن والمشروع المحدد. جهز Sprint باسم [الاسم] وبداية [التاريخ] ونهاية [التاريخ] ومنطقة [المنطقة]. تحقق من الأدوات والحقول المطلوبة والتكرار ثم أنشئها واقرأ النتيجة للتحقق.

يمكن للأدمن طلب إدارة المشاريع والسبرنتات والعناصر حسب أدوات الخادم وصلاحيات الحساب. حدد الهدف والتغيير بوضوح؛ إكمال Sprint لا يتضمن ضمنيًا إغلاق أو نقل العناصر غير المنتهية.

## 7. تحليل Git وربط التغييرات بالقصص

التشغيل الأول:

> استخدم zoho-sprints لتحليل هذا المستودع. اقرأ profile والسجل المحلي والعمليات المعلقة أولاً، وحدّث حالات عناصر Zoho المسجلة. حلل commits وstaged وunstaged وuntracked مع السياق الفعلي للكود، وحدد نطاق البداية قبل اعتماده. اربط التغييرات بالقصص والمهام الحالية، واعرض الأدلة والثقة والعناصر المقترحة بوصف دقيق ومعايير قبول. لا تنفذ كتابة في Zoho في هذه الجولة.

بعد مراجعة التقرير:

> أضف العناصر الجديدة التي تحقق ربطها وصلاحياتها. استخدم Task/Bug تحت القصص المسندة لي. أنشئ Story فقط لنتيجة مستقلة تستحق قصة بعد فحص التكرار وأهلية Sprint وتاريخها. سجل نية الإنشاء ثم المعرف والنتيجة بعد القراءة للتحقق.

مرور وقت طويل وحده لا يثبت الحاجة لقصة مستقلة، ولا يجوز استنتاج ساعات عمل فعلية من تواريخ commits.

في التشغيل التالي:

> راجع سجل التدقيق والعمليات المعلقة أولاً، ثم حدّث حالات العناصر المسجلة من Zoho. عالج التغييرات التالية لنقطة التحقق فقط، بما فيها تغيرات ملفات العمل التي سبق تحليلها. لا تكرر العناصر السابقة، واعرض أي انحراف في الفرع أو التاريخ يحتاج تحديد نطاق جديد.

تُنشأ ملفات العمل داخل المستودع:

| الملف | الاستخدام |
|---|---|
| .zoho-sprints/audit-state.json | نقطة التحقق والفرع وبصمات التغييرات |
| .zoho-sprints/change-ledger.jsonl | أحداث الربط والإنشاء والتحقق |
| .zoho-sprints/pending-actions.json | النتائج الملتبسة والعمليات التي تحتاج معالجة |
| .zoho-sprints/reports/ | تقارير التدقيق |

الوكيل ينشئ هذه الملفات ويحدثها عند تنفيذ workflow؛ التثبيت لا يشغل مزامنة خلفية. إذا التبس نجاح إنشاء عنصر فلا تعِد الإنشاء مباشرة؛ تتم المصالحة أولاً لتجنب التكرار.

## 8. مشاريع BMAD

> اقرأ مخرجات BMAD المعتمدة في [المسار]. افصل المسودات عن المعتمد، واربط القصص والمهام بمتطلبات المصدر ومعرفاته. طابقها مع Zoho والسجل المحلي، واعرض الموجود والجديد والتعارضات، ثم أضف العناصر الجديدة المسموح بها وفق دوري وقيود Sprint والإسناد. حافظ على تعديلات Zoho اليدوية وسجل تتبع كل عنصر إلى مصدره.

لا تفترض اسم مجلد BMAD؛ حدد المسار الفعلي والمخرجات المعتمدة. إعادة الاستيراد تبدأ من التتبع والسجل والمحتوى الموجود، لا من إعادة إنشاء كل الملفات.

## 9. مشكلات شائعة

| المشكلة | الإجراء |
|---|---|
| المهارة لا تظهر | تحقق من مسار Skills وانقل المجلد كاملاً، ثم حدّث الجلسة واطلب استخدامها بالاسم |
| الخادم ظاهر لكن القراءة تفشل | تحقق من العنوان والنقل والمصادقة وصلاحيات الحساب؛ ظهور الاسم لا يثبت الاتصال |
| OAuth يفتح مجددًا | تحقق من حساب المصادقة؛ ربط كل محرر قد يحتاج جلسة مستقلة |
| خطأ تشغيل npx على Windows | تحقق من Node؛ في هذا الجهاز يمكن استخدام المشغل المحلي بمسار node المطلق |
| طلب إنشاء Story متوقف | راجع تغطية التكرار وحالة Sprint وتاريخها والمنطقة الزمنية واختيار السبرنت |
| Task تحت Story مرفوضة | تحقق من نوع الأب وإسناده لمعرف المطور الفعلي وصلاحية الحساب |
| تحليل Git لا يعمل | افتح مستودع الكود الفعلي؛ مجلد توزيع المهارة وحده ليس مستودع عمل |
| عمليات قديمة بلا نتيجة | راجع pending-actions وصالحها مع Zoho قبل أي إعادة إنشاء |

## 10. ما الذي جُرّب؟

الحزمة اجتازت اختبارات التثبيت والبنية، ونجح اختبار قراءة مساحة العمل عبر المشغل المحلي في هذا الجهاز. أمثلة المحررات أعلاه مستندة إلى وثائقها، ولم تُختبر جلسة حية أو كتابة Zoho في كل محرر. راجع [تقرير الإصدار](RELEASE-REPORT.md) و[تتبع المتطلبات](docs/REQUIREMENTS-TRACEABILITY_AR.md).
