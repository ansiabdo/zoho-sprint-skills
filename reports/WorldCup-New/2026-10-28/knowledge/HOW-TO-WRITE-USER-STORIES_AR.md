# كيف تكتب قصة مستخدم — دليل عملي للمشروع

**الغرض:** دليل موحد لكتابة وتحليل قصص المستخدم في مشروع World Cup، بما يتوافق مع Zoho Sprints وBMAD وطريقة عمل Mohammed Alaqari.
**آخر تحديث:** 2026-10-28.

---

## 1. القاعدة الذهبية

القصة ليست وصفًا تقنيًا، وليست قائمة مهام. القصة تجيب على ثلاثة أسئلة:

1. **من** يحتاج القدرة؟
2. **ماذا** يريد أن يفعل؟
3. **لماذا** هذه القيمة مهمة؟

ثم تأتي معايير القبول لتجيب: **كيف نعرف أنها نجحت؟**

---

## 2. القالب الأساسي

### 2.1 بالإنجليزية (الوصف في Zoho)

```markdown
As a [role], I want [capability], so that [business value].

**Acceptance Criteria**
1. Given [context], when [action], then [observable result].
2. ...
3. ...

**Required Changes**
- [entity / DTO / permission / UI / cache / job]
- ...

**Dependencies**
- [BE01 / BE03 / external decision / data]
```

### 2.2 بالعربية (للاسم والملخص)

```text
بصفتي [الدور]، أريد [القدرة]، حتى [القيمة].
```

لا تترجم الوصف الإنجليزي حرفيًا إلى حقل الاسم العربي. الاسم العربي يجب أن يكون **قصيرًا وواضحًا** (3–8 كلمات)، والاسم الإنجليزي المختصر كذلك.

---

## 3. معايير الجودة (INVEST + Project Rules)

| المعيار | السؤال |
|---|---|
| Independent | هل يمكن تسليمها دون انتظار قصة أخرى غير مذكورة؟ |
| Negotiable | هل تركت مساحة للتفاوض على الحل، لا على القيمة؟ |
| Valuable | هل لها قيمة مستخدم/أعمال واضحة؟ |
| Estimable | هل الفريق يستطيع تقديرها؟ |
| Small | هل يمكن إنجازها داخل سبرنت واحد؟ |
| Testable | هل كل AC قابلة للاختبار؟ |

**قواعد إضافية لهذا المشروع:**

- لا تكتب قصة بلا **وصف** أو بلا **AC**.
- لا تضع اسمًا عربيًا فارغًا أو اسمًا إنجليزيًا فارغًا.
- لا تضع اسم القصة في حقل الطالب (خطأ SNA-120).
- لا تفترض أن الحالة Done تعني أن الكود موجود، أو العكس.
- لا تضع قيم الحقول الأصلية داخل الوصف وتدّعي أن الحقل مكتمل.
- لا تنشئ قصة جديدة إذا كانت موجودة في Backlog أو سبرنت مكتمل؛ اربط أو حدّث بدل التكرار.

## 4. معايير القبول: كيف تكتبها؟

### صيغة Given/When/Then

```text
Given أن المستأجر يملك خطة Starter
When يفتح المسؤول شاشة تعيين المسابقات
Then لا تظهر إلا المسابقات المصرح بها داخل الخطة
```

### صيغة مرقمة مباشرة

```text
1. حفظ إعدادات المستأجر يتحقق من WorldCup.TenantLeagues.Manage وPlan coverage.
2. Selected بقائمة فارغة لا يعرض أي مسابقة؛ AllEntitled يعرض المسابقات المصرح بها.
3. تغيير الخطة يبطل الـ caches ويعيد التحقق من الـ defaults.
```

### قواعد AC

- كل AC لها **نتيجة قابلة للملاحظة**.
- غطِّ: المسار السعيد، الأخطاء، الصلاحيات، البيانات الحدّية، التوافق، RTL/اللغة إن كان الواجهة.
- لا تخلط بين AC و«التغييرات المطلوبة»؛ AC تصف السلوك، Required Changes تصف التنفيذ.
- لا تكتب AC لا يمكن اختبارها مثل «يكون الأداء جيدًا»؛ اكتب «زمن استجابة p95 أقل من 500ms».
- للقصص التي تعتمد على مزود خارجي، أضف AC للفشل وإعادة المحاولة وعدم استدعاء المزود بلا داعٍ.

## 6. السبرنتات: القاعدة الجديدة

المطلوب: **سبرنتان كل شهر**:

- الأول: من اليوم 1 إلى اليوم 15.
- الثاني: من اليوم 16 إلى آخر يوم في الشهر.

أمثلة 2026:

| السبرنت | البداية | النهاية |
|---|---|---|
| SP6 Nov-A 26 | 2026-11-01 | 2026-11-15 |
| SP7 Nov-B 26 | 2026-11-16 | 2026-11-30 |
| SP8 Dec-A 26 | 2026-12-01 | 2026-12-15 |
| SP9 Dec-B 26 | 2026-12-16 | 2026-12-31 |

**تحذير:** النمط التاريخي في المشروع كان شهريًا (`SP0`–`SP5`). لا تنشئ سبرنتات جديدة بنمط شهري؛ استخدم النمط نصف الشهري أعلاه، واحتفظ باسم المشروع/الموضوع في نهاية الاسم.

## 7. الفرق بين Story وTask وBug

| النوع | الاستخدام | مثال |
|---|---|---|
| Story | قدرة مستخدم/أعمال كاملة | «Tenant Competition Entitlements» |
| Task | عمل تنفيذي تحت Story | «Fixture List API — League Filter» |
| Bug | خلل في سلوك موجود | «Empty selection returns all leagues» |

**قاعدة:** لا تنشئ Task بلا Story أب. لا تنشئ Bug بلا دليل سلوك متوقع/فعلي. لا تحوّل Task إلى Story لمجرد أنها كبيرة؛ أعد التفكيك.

## 9. ملحق التسليم الفعلي

عندما يكون الوصف موجودًا والتنفيذ مختلفًا/جزئيًا/بآلية أخرى، **لا تستبدل الوصف**. أضف في نهايته:

```markdown
--- [ZOHO-ACTUAL-DELIVERY v1 | SNA-XXX-YYYY-MM-DD-01] ---
الحالة: ...
ما تم فعليًا: ...
الفجوة: ...
الأدلة: BMAD ... / Git ... / ملفات ...
التحقق: لم تُشغّل اختبارات/واجهة في هذه الجولة ...
--- [/ZOHO-ACTUAL-DELIVERY | SNA-XXX-YYYY-MM-DD-01] ---
```

قواعد:

- لا تغيّر Status بسبب الملحق.
- لا تدّعِ اجتياز AC بلا دليل.
- اذكر `unverified` إذا لم تُشغّل الاختبارات.
- استخدم HTML `<hr/>` و`<div dir="rtl">` إذا كان الوصف HTML.
