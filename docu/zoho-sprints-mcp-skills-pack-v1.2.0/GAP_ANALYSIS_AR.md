# تحليل الفجوات — حزمة Zoho Sprints MCP Skills

تاريخ المراجعة: 27 أكتوبر 2026. النطاق: حزمتا `v1.0.0` و`v1.1.0` المستخرجتان، المهارة المثبتة في جذر المشروع، ونتيجة اتصال قراءة فعلي عبر MCP. لم تُنفذ أي كتابة في Zoho أثناء هذه المراجعة.

| الفجوة المثبتة | الدليل | المعالجة في v1.2.0 |
|---|---|---|
| بيانات الحزمة غير متسقة | `manifest.json` في v1.1.0 يقول 30 ملفًا، بينما المجلد وملف ZIP يحتويان 38. | عدد الملفات يحسب من الإصدار الجديد ويفحصه `scripts/validate-package.mjs`. |
| تكرار مصدر المهارة | أربع نسخ متطابقة من `SKILL.md` في v1.1.0، كل واحدة نحو 10 كيلوبايت. | مصدر واحد في `skills/zoho-sprints/`؛ أداة التثبيت تنسخ المجلد كاملًا عند الحاجة. |
| مراجع نسبية قد تنكسر بعد النسخ | نسخ `.agents` و`.claude` و`.opencode` القديمة تشير إلى `workflows/` و`prompts/` خارج مجلدها. | كل المراجع الضرورية داخل مجلد المهارة وتتحقق روابطها قبل النشر. |
| وصف الأدوات يعتمد على أمثلة قديمة | المحادثة السابقة قالت إن إكمال Sprint غير متاح؛ اتصال 27 أكتوبر أظهر `ZohoSprints_CompleteSprint` ضمن 83 أداة. | المرجع يذكر المشاهدة المؤرخة ويُلزم اكتشاف الأدوات والمخططات في كل جلسة. |
| مخططات أدوات Zoho ليست موحدة | `getItemTypes` يستخدم رأسًا من نوع boolean بحروف مختلفة عن أدوات القراءة والكتابة الأخرى. | تعليمات صريحة لاستخدام مخطط الأداة المختارة حرفيًا، بلا قالب وسائط عام. |
| تغطية البحث غير محددة بما يكفي | أدوات المشاريع وSprints والعناصر والمستخدمين مرقمة الصفحات، و`GetItems` مقيد بـ Sprint. | تسجيل الصفحات والنطاق والمشاريع وSprints المفحوصة، وذكر أي نقص قبل حكم «لا يوجد تكرار». |
| الهوية والدور غير مهيأين | القالب القديم يحوي معرف مستخدم ومساحة عمل فارغين مع `developer` كقيمة افتراضية. | قالب جديد بقيم `null` لمنع افتراض الدور؛ التحقق من معرف المستخدم الفعلي قبل عمليات Developer. |
| السجل المحلي إرشادي فقط | v1.1.0 يصف JSONL وcheckpoint، ولا يوفر منفذًا تلقائيًا لتدقيق Git. | مرجع أوضح للكتابة المسبقة، حالات النتائج الغامضة، التحديث الذري، واستعادة التشغيل. ما زال تنفيذ تدقيق Git عملًا ينفذه المساعد عند الطلب؛ لا تدعي الحزمة تشغيلًا تلقائيًا. |
| دعم المحررات مبالغ فيه إذا لم يختبر | الحزمة القديمة تحتوي مسارات وأمثلة لعدة محررات، لكن الاختبار الفعلي السابق كان مع Codex فقط. | أداة تثبيت للمسارات المحلية المعروفة، ومؤشرات خفيفة لـ Cursor/Kiro، ودليل يميز الاختبار الفعلي من الإرشاد غير المجرب. |
| لا يوجد فحص إصدار متكرر | الحزمة القديمة بلا اختبار تثبيت أو تحقق من الروابط والعدد. | اختبارات `node:test` لأداة التثبيت وفاحص للحزمة، بالإضافة إلى مدقق المهارات في Codex. |

## حدود باقية مقصودة

- المهارة سياسة للمساعد وليست نظام صلاحيات. حساب Zoho المتصل هو الذي يفرض الوصول الحقيقي.
- لا تتضمن الحزمة رابط MCP الخاص أو رموز OAuth أو ملف إعداد الاتصال المحلي. يجب إعداد الاتصال في المحرر على حدة.
- لا ينشئ هذا الإصدار عنصرًا في Zoho ولا يشغل تدقيق Git تلقائيًا. يلزم مشروع Git فعلي، ملف دور وهوية موثق، وطلب تشغيل محدد.
- توافر أداة `CompleteSprint` لا يثبت أن الحساب يستطيع استخدامها أو أن متطلبات إكمال Sprint مستوفاة.
