# Approved BMAD artifacts → Zoho Sprints

Use this only when the user or trusted project configuration says the project uses BMAD and identifies accessible artifacts. Do not infer the method or version from directory names. Determine the project's source-of-truth order and approval state for briefs, PRDs, architecture, epics, stories, tasks, and tests.

Build a traceability map: source artifact and stable section ID → capability/epic → independently valuable User Story and acceptance criteria → implementation Task/Bug → test evidence. Record source paths relative to the repository and section IDs; do not paste entire documents into Zoho.

Before import, read the existing Zoho project and relevant item pages, inspect plausible matches, and check the local ledger. Show proposed title/type, target parent and sprint, source reference, duplicate result, confidence, and blockers. Apply [role and operation rules](roles-and-operations.md), including Developer parent assignment and Active sprint date eligibility. An approved BMAD artifact is planning evidence, not authorization for an external write by itself.

On repeat runs, compare stable artifact IDs and allowed content fingerprints with recorded imports. When a source changes, show the difference and propose a controlled update. Preserve edits already made in Zoho unless the user authorized merging them. Leave conflicting or incomplete requirements pending rather than guessing.
